A listing that sits in the wrong category with half its item specifics blank is not hard to fix. It is just tedious, and it multiplies by every SKU you have. We do that work in volume, check it by hand, and give you a file that loads cleanly.

## What you get

- Titles written for search, using eBay's 80-character limit properly.
- Condition fields set consistently, with a short condition note where the category allows one.
- Variation listings built from single SKUs, with the right variation attributes.

## How we handle eBay's catalogue rules

**Item specifics.** These are the structured fields (brand, model, size, colour, style and so on) that eBay uses to match your item to what a buyer typed or filtered by. Which ones exist depends on the category, so we pull the list per category rather than reusing one template. Most supplier files we see cover brand and little else.

**Category mapping.** One wrong category affects the item specifics you are offered, the filters you appear in and the fees that apply. We map by what the product is, not by what the supplier called it, and flag borderline items for you.

**Titles.** eBay's help pages say to keep titles to 80 characters or fewer, use words buyers search for, spell correctly and avoid all-caps and symbols. We put brand, product type, model and the key distinguishing attribute first, and drop anything that only decorates.

**Variations.** A shirt in five sizes and four colours should be one listing with variations, not twenty. We group SKUs, choose the variation attributes the category supports, and check each child row carries a value for each.

**Condition.** Condition options depend on the category, and a few categories restrict some of them. We set the field to what your data states and never upgrade "used" to something kinder.

**Images.** Buyers judge on the first photo. We check the main image is clean, the order makes sense, and every link resolves. Platform minimums and limits change, so we verify against eBay's current photo guidance when we build the file.

### Best Match, described honestly

eBay says its Best Match sort weighs several things: how well a listing fits the search, how popular the item is, price, listing quality, how complete the listing is, terms such as returns and handling time, and the seller's track record. eBay does not publish weightings, and neither will we. What we control is the listing side: relevance, completeness and quality.

## Bulk upload routes

eBay's help pages list several. Seller Hub Reports (formerly File Exchange) takes CSV files and suits most catalogues. The Bulk Listing Tool in Seller Hub handles medium volumes with less setup. Merchant Integration Platform, the Inventory API and the Sell Feed API suit larger or integrated operations. We build for the first two, and can format a feed if you run one of the others.

## What we do not do

We do not manage your eBay account, answer buyer messages, handle disputes or returns, run promoted listings, or reprice. If an account restriction is blocking you from listing, that is between you and eBay. We do listing data, and we are better for staying there.
