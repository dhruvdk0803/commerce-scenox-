## What you get

Fashion data is mostly repetition done carefully. One style becomes twenty rows, and every row has to agree with the others. This is what we deliver:

- Every style built as one product with its colour and size variants, each with a unique, consistent SKU.
- Titles written to a pattern you approve, for example brand, fit, garment, colour.
- Fabric, care, fit and model-height details placed in a consistent spot, not buried in a paragraph.
- Size charts attached by fit group, with a "how to measure" block where you supply the guidance.
- Images matched to colours, ordered with the main image first, with alt text.
- Collections and tags by gender, category, season and occasion.
- SEO titles and meta descriptions.
- A QA report listing every style with a missing size, price, image or measurement.

## How it works

1. You send your supplier sheets, line lists or an export from your current store, plus an image folder.
2. We inspect the files and send a fixed quote before work starts. A 10-product sample is free if the project is a fit.
3. Our AI engine maps and drafts the catalog at volume. A person reviews every output, especially variant logic and size data.
4. You approve a draft or staging state. Nothing goes live before that.
5. We publish through a staff or collaborator account you can remove at any time. We never ask for store passwords.

Turnaround is from 48 hours for eligible projects; turnaround depends on scope, catalog complexity and the quality of the data and access we receive.

## What fashion catalogs get wrong

### Size runs and option limits

Shopify allows three options per product, so a style with colour, size and length (say, trousers in regular and long) needs a decision. Usually length becomes part of the size value or a separate product. WooCommerce handles more attributes but variation counts get heavy. We pick one pattern and apply it to the whole catalog.

### Sizing systems

Footwear and clothing sizes change meaning by market. A UK 8 shoe is not a US 8. We keep the size label your customer expects on the product and carry the size system in the feed, so a Google listing is not rejected for ambiguous sizes.

### Colour names and swatches

Suppliers write "Navy", "Midnight" and "Dark Blue" for one shade. We normalise to a short list of filterable colour families and keep the brand colour name as the display value. Swatches need a consistent hex or image per colour; we use the product image crop unless you send swatch files.

### Image types

| Image type | Best used for | Catalog handling |
|---|---|---|
| Model shot | Hero image, fit and drape | First image per colour |
| Flat-lay | Detail, pattern, print | Second or third position |
| Ghost mannequin | Shape without a model | Consistent across the range |

Mixing the three without a rule makes a collection look unfinished. We order them the same way for every style.

### Ethnic wear

Sarees, lehengas, kurta sets and dupatta combinations are bundles. We separate what is included (kurta, bottom, dupatta), note blouse piece or stitched, and keep fabric, work type and occasion as filterable fields.

## Attribute table

| Field | Example | Used for |
|---|---|---|
| Colour | Navy | Filter, variant, Google feed |
| Size | M, UK 8, 32 | Variant, size chart link |
| Size system and type | UK, regular | Google feed |
| Gender and age group | Female, adult | Google feed, collections |
| Material | 100% cotton | Description, feed |
| Care | Machine wash cold | Product page |
| Fit | Slim, relaxed | Filter, title |
| Item group ID | Style code | Groups variants in feeds |
| Model height and size worn | 5'9", wearing M | Reduces returns |

Google's apparel requirements vary by country and subcategory, so we check the current Merchant Center help pages for your target markets before filling these.
